# Соответствие заданию

Проверено 24 сентября 2026 года по [исходному PDF «Тестовое задание на должность — Фронтенд разработчик React (v5)»](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view).

## Требования PDF

| № | Требование | Реализация и проверка |
| --- | --- | --- |
| 1 | Отправка и получение сообщений MAX | Реализованы подключение инстанса, создание личного чата и обмен текстом. Интерфейс проверен с подменёнными ответами API и с действующим инстансом MAX. |
| 2 | Использовать GREEN-API | Прямые HTTPS-запросы к GREEN-API, адрес из кабинета можно указать при подключении. Контракт запросов проверен тестами. |
| 3 | Только текстовые сообщения | Отправка текста до 4000 символов, приём `textMessage` и `extendedTextMessage`. Медиа и служебные события пропускаются с подтверждением очереди. |
| 4 | Ориентир внешнего вида — web.max.ru | Тёмная палитра, фиолетовый акцент, список чатов, область переписки и нижнее поле ввода. Это самостоятельный минимальный интерфейс, без заявления о точной копии MAX. Проверены настольный вид и ширина 390 px. |
| 5 | Минимум функций | Только подключение, номер получателя, выбор чата, текстовая переписка и выход. Без вложений, звонков, групп и дополнительных экранов. |
| 6 | Отправка через SendMessage | `POST /waInstance{idInstance}/sendMessage/{apiTokenInstance}` с `chatId` и `message`. Полученный `idMessage` означает принятие API; интерфейс не выдаёт его за доставку. |
| 7 | Получение через HTTP API receiving | Последовательные `ReceiveNotification` и `DeleteNotification`, защита от дублей, повторы временных ошибок и отмена запросов при выходе. Проверены порядок обработки и повтор подтверждения. |
| 8 | React | React + TypeScript + Vite. Зависимости приложения — только React и React DOM. |

## Пользовательский сценарий

| Шаг | Результат проверки |
| --- | --- |
| Ввод `idInstance` и `apiTokenInstance` | Поля, валидация, ожидание и ошибки реализованы; подключение проверяет `GetStateInstance`. |
| Ввод номера и создание чата | `CheckAccount` возвращает идентификатор MAX; повторный номер открывает существующий чат. Проверено с подменёнными ответами. |
| Отправка текста | Запрос, появление сообщения, переносы строк, emoji и сохранение черновика при ошибке проверены с подменёнными ответами. |
| Появление сообщения у получателя в MAX | Проверено с действующим инстансом и реальным получателем. |
| Ответ получателя появляется в интерфейсе | Проверено через ReceiveNotification и DeleteNotification с реальным ответом из MAX. |

## Дополнительные условия проекта

- Проект проверен в отдельной рабочей папке; исходники и итоговая сборка сверены после переноса.
- TypeScript, ESLint и production-сборка прошли; автоматические тесты — 9 из 9.
- Сервер разработки и просмотр готовой сборки открываются в браузере. На экране подключения ошибок консоли нет; валидация неверного идентификатора работает.
- Есть состояния ожидания, сообщения об ошибках, проверка номера, адреса API и длины текста.
- Ключ, переписка и черновики хранятся только в памяти вкладки; постоянное хранилище не используется. Секретов в исходниках нет.
- В README описаны локальный запуск, настройка инстанса, ограничения очереди и публикация. `.env.example` содержит только публичный адрес API.
- Для GitHub подготовлены `.gitignore`, lock-файл и workflow автоматических проверок.
